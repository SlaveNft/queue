# QUEUE v3 — the contract with operator liability

**Status: NEAR testnet, not audited.** Source: [`contracts/queue-v3`](../contracts/queue-v3). Deployed at
[`market5.queue-demo.testnet`](https://testnet.nearblocks.io/address/market5.queue-demo.testnet).

v3 keeps every v2 rule (posted asks, deadline-checked purchases, balances held in the contract, model-signature
settlement) and makes the remaining trusted parts accountable: the operator, the owner, the price a slot holder
can charge, and the storage a job leaves behind.

## What v3 guarantees

| # | Rule | Enforced by |
| --- | --- | --- |
| G1 | A job passed by a purchase is paid its posted ask × the buyer's duration and still finishes before its stated deadline, with a safety margin. | `quote_internal`, unchanged from v2 |
| G2 | **A slot holder cannot reprice when an urgent job appears.** Raising an ask takes effect 30 s later; a cut is immediate. Quotes always use the ask in force. | `set_move_ask`, `ASK_RAISE_DELAY_SECS` |
| G3 | **A job already projected to miss cannot block a purchase.** It has no promise left to protect; it is still paid its ask. Every job that is still on schedule keeps G1. | `quote_internal` (the `doomed` check) |
| G4 | **Buy in the same transaction as the submission.** `submit_job(…, priority)` buys the slot atomically; `required: true` makes the whole submission fail if the slot cannot be had. By default it buys only if the job's own deadline needs it. | `submit_job` |
| G5 | **The operator is liable for its promises.** A job that was on schedule when admitted (or after its own purchase) and then misses or fails is paid back its priority spend plus a penalty equal to its reward, from the operator's stake, as far as the stake goes. | `pay_broken_promise`, `stake` |
| G6 | **No new work without a live, staked operator.** Submissions and purchases are refused (nothing is charged) when the stake is below the minimum or the operator has not called the contract for 180 s. Cancellations, timeouts and withdrawals always work. | `require_accepting_work`, `heartbeat` |
| G7 | **Model jobs are paid only for a verified model answer.** A job whose input is a request sha256 (with a model key pinned) settles only through `complete_job_attested`; the operator's word is refused. Without an answer the operator can only fail the job (full refund, G5 penalty). | `complete_job`, `Verify` |
| G8 | **Refusing work costs the operator, not the user.** `reject_job` (queued jobs only) returns reward and bond, returns the priority spend from the stake, and releases the record. Because that refund comes from the operator, the operator chooses whose jobs it takes (G12). | `reject_job` |
| G9 | **Storage comes back whole.** A job holds 0.017 NEAR for its record and a purchase 0.006 + 0.003 per job passed. `release_job` deletes the finished job's records and credits the deposits back to the owner (owner any time, anyone after 7 days). Kept back are only the bytes that stay in the contract: the "answered" marker of a model-settled job (about 0.001 NEAR) and any balance key the job or its purchase had to create. | `release_job` |
| G10 | **The contract's admin methods wait 24 h.** Operator, treasury, fee, minimum stake, model key and the contract's own upgrade method go through `propose` → `execute_proposal` / `execute_upgrade` after the timelock; anyone can execute, the owner can cancel. Only pause is immediate (it stops new work; the queue still drains). **Limit on testnet today:** the contract account still holds a test full-access key, and that key can replace the code directly, without the timelock (see below). | `propose`, `timelock_secs` |
| G11 | **The operator cannot run with the stake.** Unstaking waits the same 24 h, and a withdrawal is refused while any job is queued or running, so the stake cannot leave under an open promise. The operator cannot be replaced while a job is open either (checked when the change runs, not when it was proposed); a new operator does not inherit the old one's stake (it is returned to the old operator). | `request_unstake`, `withdraw_unstaked`, `execute_proposal` |
| G12 | **A closed list of clients.** Wherever a stake backs the queue, only accounts the operator approved (`allow_clients`) can submit; anyone else is refused before escrow, storage or a purchase. The stake pays for refusals and broken promises, so an open door would let a stranger collect from it: buy a slot from its own second job, have the job refused, keep the compensation and get the price back from the stake. This deployment is a closed pilot: the eight season accounts are approved. | `allow_clients`, `remove_client`, `is_client` |

What it still trusts: the operator for liveness (now paid for by its stake) and, for operator-verified jobs, for the
artifact; NEAR AI's attestation that the pinned key lives in TEE hardware (checked off chain before pinning); the
deadlines and asks agents state (a contract cannot check that a deadline is true).

Limits, stated plainly:

- **Compensation is capped by the stake.** The minimum stake (0.5 NEAR here) is a floor, not a reserve per job: if
  broken promises add up to more than what is left of the stake, the last ones are paid only in part.
- **Approved clients can still cost the operator money.** Two approved accounts acting together can do what a
  stranger no longer can (G12). The operator answers that by choosing its clients and removing one that abuses it.
- **Bytes nobody deposits for.** A release returns the deposit less the bytes that stay, so storage is paid by
  whoever causes it, with two bounded exceptions paid from the contract account's own balance: the activity log (a
  fixed ring of 128 entries), and a balance key created by a payout rather than by its owner (a penalty or a
  priority refund from the stake, the treasury's fee balance, a returned stake): at most one key of about
  0.00125 NEAR per account. The random-history test checks after every step that the bytes in storage are covered by
  the deposits held and the money kept; `npm run verify:v3` checks on chain that the contract's balance covers
  everything it owes plus every byte it stores, and prints the margin.
- **The test full-access key bypasses the timelock.** `market5` keeps the key it was deployed with, so the code
  can be fixed on testnet; this build was installed with it. Whoever holds that key can replace the contract at
  once. Removing it is a single transaction that cannot be undone, and it has not been sent. Until it is, read G10
  as "the contract's admin methods wait 24 h", not "nobody can change the contract in under 24 h".
  `npm run verify:v3` prints how many full-access keys the account holds.

Amounts are small on purpose (rewards 0.002 NEAR, asks 0.000001 NEAR/s); the rules do not depend on the size.


## Reproduce

```bash
npm run build:contract-v3     # wasm in contracts/queue-v3/target/wasm32-unknown-unknown/release
npm run deploy:v3             # testnet: market5 + stake + agent balances and keys (idempotent)
npm run proof:v3              # the on-chain proof (about 7 minutes, no model)
npm run proof:v3-client       # one job through packages/client with a function-call key (30 s)
npm run proof:v3-table        # rewrite the proof table above from data/v3/proof.json
npm run verify:v3             # re-check all of it, no keys
```
